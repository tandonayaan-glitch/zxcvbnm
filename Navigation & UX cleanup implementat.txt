DIAGNOSTICS

Root cause: getPlatformDiagnostics() ran getCountFromServer(collectionGroup(db, 'deliveries')). firestore.rules grants public read only on matches/{id}/deliveries/{ballId} — there is no match /{path=**}/deliveries/{ballId} rule — so the collection-group aggregate was permission-denied and rejected the entire Promise.all, so the whole panel fell through to "Couldn't load diagnostics".

Fix (no rule change): the deliveries total is now summed from each match's own matches/{id}/deliveries count — every one of which is covered by the existing allow read: if true — enumerated from matches and fanned out with a concurrency limit of 24. A match whose count can't be read is tracked and surfaced as a partial total, never silently counted as zero. The error branch now renders the actual failure message plus a "Try again" button.

Verified live against the wiped database: panel loads, shows Players 0 / Matches 0 / Deliveries 0 (real counts, not fabricated), no error state.

SIGN OUT

useSignOut() is the one mechanism:

authStore.logout() → signOut(auth) (terminates the Firebase session); observeAuth + an explicit set({ profile: null }) in a finally clear client auth state even if the network call throws
redirect to /login with { replace: true } so Back can't re-enter a protected screen on stale in-memory state
a failed sign-out call is surfaced (toast) but never blocks the redirect

<SignOutButton> wraps it, exposed in: app-shell sidebar (desktop and mobile drawer — both verified), public site header, UserSettingsPage ("Sign out this device"), and ActivatePage. ProtectedRoute already renders <Navigate to="/login" replace> whenever profile is null, so protected routes are not reachable post-logout. Sign Out and "Exit scoring" are deliberately kept distinct.
